## 1. 문제 정의

### 사용자 피드백
> "진도 모달에서 교재를 넣으려고 할 때 드롭박스에 너무 많은 교재들이 나와서 고를 수가 없어"

### 현재 구현 분석

**데이터 소스** ([useProgress.ts:339-397](../frontend/src/hooks/backoffice/useProgress.ts#L339-L397)):
```typescript
// 1. class_textbooks: 반에 연결된 교재 (적절함)
// 2. progress 테이블: 이전에 사용된 모든 교재 (문제!)
const { data: progressData } = await supabase
  .from('progress')
  .select('textbook')
  .not('textbook', 'is', null);  // ← 전체 진도 기록의 모든 교재!
```

**UI 구현** ([TextbookAutocomplete.tsx](../frontend/src/components/backoffice/modals/TextbookAutocomplete.tsx)):
- 입력값이 없으면 **처음 10개**만 표시 (`textbooks.slice(0, 10)`)
- 검색어가 있으면 **필터링된 10개** 표시

### 핵심 문제점

| 문제 | 설명 | 영향 |
|------|------|------|
| **데이터 범위 과다** | 전체 progress 테이블의 모든 교재를 조회 | 수십~수백 개의 교재가 목록에 포함 |
| **맥락 무시** | 현재 반과 무관한 교재도 표시 | "고3 미적분" 반에서 "초등 수학" 교재 노출 |
| **우선순위 부재** | 모든 교재가 동등하게 나열 | 최근/자주 사용 교재 구분 불가 |
| **시각적 구분 없음** | 반 연결 교재 vs 기타 교재 구분 없음 | 중요 정보 파악 어려움 |

## 2. 인지 심리학 분석

### 2.1 Hick의 법칙 (선택의 역설)
> 선택지가 많을수록 결정 시간이 **로그 비례**로 증가

```
선택지 수   결정 시간
2개         ~0.5초
5개         ~1초
10개        ~1.5초
50개        ~3초+ (과부하)
100개+      포기 또는 랜덤 선택
```

**현재 상황**: 수십~수백 개의 교재 → 사용자 과부하

### 2.2 Miller의 법칙 (7±2 규칙)
> 단기 기억은 **5~9개** 항목만 효과적으로 처리

**권장**: 초기 노출 항목을 **5~7개**로 제한

### 2.3 근접성의 원리 (Proximity)
> 관련 있는 항목은 **가까이** 배치해야 함

**문제**: 반에 연결된 교재와 무관한 교재가 섞여서 표시

## 3. 토스 UX 철학 적용

### 3.1 "한눈에" 원칙
> 사용자가 **생각하지 않아도** 즉시 선택할 수 있어야 함

```
❌ 나쁜 예 (현재):
┌──────────────────────────────┐
│ 🔍 교재 검색...              │
├──────────────────────────────┤
│ 개념원리 RPM 고1             │ ← 관련 있음
│ 개념원리 수학 중1            │ ← 관련 없음
│ 고등 수학의 정석 기본        │ ← 관련 없음
│ 기초 연산 초등 6학년         │ ← 관련 없음!
│ 라이트쎈 고1 공통수학        │ ← 관련 있음
│ 마플 교과서 미적분           │ ← 관련 없음
│ 베이직쎈 고1 공통수학        │ ← 관련 있음
│ ... (50개 더)                │
└──────────────────────────────┘
"뭐가 우리 반 교재지?"

✅ 좋은 예 (개선안):
┌──────────────────────────────┐
│ 🔍 교재 검색...              │
├──────────────────────────────┤
│ 📚 이 반 교재                │
│   베이직쎈 고1 공통수학      │ ← 반 연결
│   개념원리 RPM 고1           │ ← 반 연결
├──────────────────────────────┤
│ 🕒 최근 사용                  │
│   라이트쎈 고1 공통수학      │ ← 최근 진도
├──────────────────────────────┤
│ 💡 다른 교재 검색...         │
└──────────────────────────────┘
"아, 베이직쎈이네!"
```

### 3.2 Progressive Disclosure (점진적 노출)
> 필요한 정보만 **단계적**으로 제공

| 단계 | 노출 내용 | 트리거 |
|------|----------|--------|
| 1 | 반 연결 교재 (2~5개) | 드롭다운 열기 |
| 2 | 최근 사용 교재 (1~3개) | 스크롤 또는 기본 표시 |
| 3 | 전체 검색 | 검색어 입력 시 |

### 3.3 "빠른 탈출" 원칙
> 원하는 결과에 **최소 클릭**으로 도달

**현재**: 검색 → 스크롤 → 선택 (3단계)
**개선**: 클릭 → 선택 (2단계) 또는 자동 선택 (1단계)

## 5. 권장 솔루션

### 추천: Option B + C 조합 (스마트 그룹핑)

#### 5.1 데이터 로직 개선

```typescript
// useTextbooks 훅 개선안
async function getTextbooksForProgress(classId: string, lastTextbook?: string) {
  // 1. 반 연결 교재 (최우선)
  const linkedTextbooks = await getLinkedTextbooks(classId);

  // 2. 이 반의 최근 진도에서 사용된 교재 (해당 반만!)
  const recentlyUsed = await supabase
    .from('progress')
    .select('textbook')
    .eq('class_id', classId)  // ← 핵심: 해당 반만 조회
    .order('date', { ascending: false })
    .limit(5);

  // 3. 지난 진도 교재 (자동 입력용)
  const autoFillTextbook = lastTextbook;

  return {
    linked: linkedTextbooks,      // 반 연결 교재
    recent: recentlyUsed,         // 최근 사용
    autoFill: autoFillTextbook,   // 자동 입력 추천
  };
}
```

## 6. 구현 우선순위

### Phase 1: 데이터 범위 축소 (핵심 수정)
```typescript
// Before: 전체 progress 테이블
.from('progress').select('textbook')

// After: 해당 반의 progress만
.from('progress').select('textbook').eq('class_id', classId)
```

**예상 효과**: 교재 수 90% 감소 (전체 → 해당 반)

### Phase 2: 그룹핑 UI 추가
- 섹션 헤더: "이 반 교재" / "최근 사용" / "검색 결과"
- 시각적 구분: 배경색, 아이콘

### Phase 3: 스마트 자동 입력
- 지난 진도 교재 → 오늘 교재 필드 자동 입력
- 이미 일부 구현됨 (ProgressModal.tsx:159-175)

## 7. 결론

### 문제 요약
| 현재 | 개선 후 |
|------|---------|
| 전체 교재 50~100개+ | 해당 반 교재 2~5개 |
| 맥락 없는 목록 | 그룹화된 우선순위 목록 |
| 매번 검색 필요 | 자동 입력 + 1클릭 선택 |

### 핵심 개선점
1. **데이터 범위**: 전체 → 해당 반 (class_id 필터)
2. **우선순위**: 반 연결 > 최근 사용 > 기타
3. **자동 입력**: 지난 진도 교재 자동 채우기

### 토스 UX 원칙 적용
- ✅ "한눈에": 관련 교재만 즉시 노출
- ✅ Progressive Disclosure: 필요 시에만 전체 검색
- ✅ "빠른 탈출": 1클릭 또는 0클릭으로 선택 완료

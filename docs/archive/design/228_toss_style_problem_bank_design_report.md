# 토스라면 어떻게 만들었을까? - 문제은행 UI 연구 리포트

**작성일**: 2025-12-09
**목적**: 토스 디자인 원칙을 문제은행 UI에 적용하는 방안 연구

---

## 1. 토스 디자인 철학 핵심

### 1.1 한 문장 정의

> **"사용자가 생각하지 않도록 한다."**

토스의 UI/UX는 사용자가 별도의 학습 없이 직관적으로 서비스를 이용할 수 있도록 설계됩니다.

### 1.2 Product Principles (제품 원칙)

| 원칙 | 설명 | 문제은행 적용 |
|------|------|--------------|
| **1 Thing per 1 Page** | 하나의 화면에 하나의 명확한 목표 | 검색/필터/보기를 분리 |
| **Minimum Features** | 꼭 필요한 기능만 | 핵심 기능 우선, "있으면 좋은" 기능 제거 |
| **Clear CTA** | 명확한 다음 단계 | 주요 액션 버튼 강조 |
| **Minimum Input** | 최소한의 터치로 완료 | 한 번의 탭으로 문제 선택 |
| **Casual Concept** | 친숙하고 이해하기 쉽게 | 전문 용어 대신 일상 언어 |

> 참고: [pxd story - 토스 디자인 컨퍼런스 후기](https://story.pxd.co.kr/1411)

## 2. 토스 디자인 시스템 (TDS) 분석

### 2.1 TDS 핵심 구성

```
TDS (Toss Design System)
├── 컴포넌트 라이브러리 (수백 개)
├── UX 라이팅 가이드
├── 아이콘 시스템
├── 인터랙션 패턴
└── 접근성 가이드
```

### 2.2 가이드 구성 원칙

1. **선형적 읽기**: 위에서 아래로 자연스러운 흐름
2. **계층적 정보**: 상위 옵션 → 내부 요소 → 상세 스펙
3. **최악의 케이스 우선**: 모든 옵션 사용 시 모습을 먼저 제시
4. **접근성 의무화**: 모든 컴포넌트에 접근성 가이드 포함

> 참고: [토스 기술 블로그 - 디자인 시스템 가이드](https://toss.tech/article/toss-design-system-guide)

### 2.3 TDS의 효과

| 지표 | 개선 효과 |
|------|----------|
| 개발 속도 | 커스텀 UI 대비 **3~5배 빠름** |
| 시간 절약 | 6개월간 **4,500시간** (562일) 절약 |
| 생산성 | 메이커 1인당 하루 평균 **1시간** 절약 |

## 3. 토스 스타일 문제은행 UI 설계

### 3.1 현재 vs 토스 스타일 비교

#### 현재 문제은행

```
┌─────────────────────────────────────────┐
│ [검색] [그룹화▼] [뷰▼] [다중선택] [삭제]│  ← 기능 버튼 나열
├─────────────────────────────────────────┤
│                                         │
│  ┌───┐ ┌───┐ ┌───┐ ┌───┐ ┌───┐ ┌───┐  │
│  │   │ │   │ │   │ │   │ │   │ │   │  │  ← 그리드 나열
│  └───┘ └───┘ └───┘ └───┘ └───┘ └───┘  │
│  ... (1000개 이상)                      │
│                                         │
└─────────────────────────────────────────┘
```

**문제점**:
- 1000개 문제가 한 화면에 (스크롤 지옥)
- 여러 기능이 한 화면에 혼재
- 특정 문제 찾기 어려움

#### 토스 스타일 재설계

```
┌─────────────────────────────────────────┐
│ 📚 문제은행                              │
│                                         │
│  1,234개의 문제를 보관하고 있어요        │  ← Casual Concept
│                                         │
│  ┌─────────────────────────────────┐   │
│  │ 🔍 문제 검색                     │   │  ← 검색 우선
│  └─────────────────────────────────┘   │
│                                         │
│  ┌────────────────┐ ┌────────────────┐ │
│  │ 📖 교재별 보기  │ │ 📅 최근 추가   │ │  ← 명확한 진입점
│  │ 5개 교재       │ │ 오늘 12개      │ │
│  └────────────────┘ └────────────────┘ │
│                                         │
│  ─────────────────────────────────────  │
│                                         │
│  최근 작업한 문제                        │
│  ┌───┐ ┌───┐ ┌───┐ ┌───┐             │
│  │ 1 │ │ 2 │ │ 3 │ │ 4 │  →          │
│  └───┘ └───┘ └───┘ └───┘             │
│                                         │
└─────────────────────────────────────────┘
```

### 3.3 Minimum Features 적용

#### 제거할 기능 (있으면 좋지만 복잡성 증가)

| 기존 기능 | 결정 | 이유 |
|----------|------|------|
| 그리드/리스트 토글 | ❌ 제거 | 그리드만 제공 (이미지 확인 필수) |
| 다중 선택 모드 | 🔄 숨김 | 필요시 진입 (기본 숨김) |
| 그룹화 옵션 | ✅ 단순화 | "문서별"만 유지 |
| 고급 필터 | 🔄 분리 | 별도 화면으로 분리 |

#### 핵심 기능만 유지

```
메인 화면 기능:
1. 검색 (스마트 검색)
2. 교재별 보기
3. 페이지별 보기

숨김 기능 (길게 누르기 or 메뉴):
- 다중 선택/삭제
- 내보내기
- 통계
```

## 5. 토스 스타일 UX 라이팅

### 5.1 기존 vs 토스 스타일

| 기존 | 토스 스타일 |
|------|------------|
| 문제은행 (1234) | 1,234개의 문제를 보관하고 있어요 |
| 필터 적용됨 | 베이직쎈 문제만 보고 있어요 |
| 검색 결과 없음 | 찾는 문제가 없어요. 다른 검색어를 입력해 보세요 |
| 삭제하시겠습니까? | 이 문제를 삭제할까요? |
| 확정 완료 | 문제은행에 등록했어요 ✓ |
| 오류 발생 | 문제가 생겼어요. 다시 시도해 주세요 |

### 5.2 상태 표시

```
// 로딩 중
"문제를 불러오고 있어요..."

// 빈 상태
"아직 등록된 문제가 없어요
라벨링 화면에서 문제를 확정해 보세요"

// 필터 결과 없음
"조건에 맞는 문제가 없어요
필터를 조정해 보세요"

// 성공
"12개의 문제를 내보냈어요 ✓"

// 확정
"문제은행에 등록했어요"
```

## 6. 컴포넌트 설계

### 6.1 문제 카드 (토스 스타일)

```tsx
// ProblemCard.tsx - 토스 스타일
function ProblemCard({ problem, onTap, onLongPress }) {
  return (
    <motion.div
      className="bg-white rounded-2xl p-4 shadow-sm"
      whileTap={{ scale: 0.98 }}
      onTap={onTap}
      onLongPress={onLongPress}
    >
      {/* 이미지 영역 - 둥근 모서리 */}
      <div className="aspect-[4/3] bg-grey-100 rounded-xl overflow-hidden mb-3">
        <img src={problem.thumbnail} className="w-full h-full object-cover" />
      </div>

      {/* 정보 영역 */}
      <div className="space-y-1">
        <p className="text-sm font-semibold text-grey-900">
          {problem.problemNumber}번
        </p>
        <p className="text-xs text-grey-500">
          {problem.bookName} · {problem.page}p
        </p>
      </div>

      {/* 상태 뱃지 - 우측 하단 */}
      {problem.status === 'confirmed' && (
        <div className="absolute bottom-2 right-2">
          <span className="text-xs text-toss-blue">확정됨 ✓</span>
        </div>
      )}
    </motion.div>
  );
}
```

## 7. 페이지 전환 전략

### 7.1 토스 스타일 네비게이션 흐름

```
[홈] ──→ [문제은행 메인] ──→ [교재별 목록] ──→ [문제 목록]
                │                              │
                │                              ↓
                └──→ [검색 결과] ───────────→ [문제 상세]
```

### 7.2 각 화면의 역할

| 화면 | 목표 | 주요 액션 |
|------|------|----------|
| 문제은행 메인 | 탐색 방법 선택 | 검색, 교재별, 최근 |
| 교재별 목록 | 교재 선택 | 교재 탭 |
| 문제 목록 | 문제 확인 | 문제 탭, 필터 |
| 문제 상세 | 상세 확인 & 액션 | 확정, 삭제, 연결 |
| 검색 결과 | 빠른 찾기 | 문제 탭 |

---

## 8. 구현 우선순위

### Phase A: 핵심 구조 개편 (4-6시간)

```
1. 메인 화면 재설계
   - 검색 바 상단 배치
   - 빠른 접근 카드 추가
   - 최근 작업 섹션

2. 교재별 목록 화면
   - 교재 카드 리스트
   - 문제 수, 해설 연결률 표시
```

### Phase B: 문제 목록 개선 (3-4시간)

```
1. 페이지별 그룹화 고정
2. 점진적 로딩 ("더보기" 버튼)
3. 문제 카드 토스 스타일 적용
```

### Phase C: 상세 & 액션 (2-3시간)

```
1. 바텀 시트 상세 뷰
2. 스와이프 액션
3. UX 라이팅 개선
```

### Phase D: 스마트 검색 (2-3시간)

```
1. 자연어 검색 파싱
2. 검색 제안
3. 최근 검색 기록
```

## 9. 핵심 차별점 요약

| 관점 | 일반적인 접근 | 토스 스타일 |
|------|-------------|------------|
| **정보 표시** | 한 화면에 모든 정보 | 화면별 하나의 목표 |
| **기능** | 모든 기능 노출 | 핵심만 노출, 나머지는 숨김 |
| **검색** | 단순 텍스트 매칭 | 자연어 스마트 검색 |
| **로딩** | 전체 로드 | 점진적 로드 |
| **피드백** | 시스템 메시지 | 친근한 대화체 |
| **인터랙션** | 버튼 클릭 | 제스처 + 버튼 |

## 10. 결론

### 토스가 문제은행을 만든다면:

1. **"1 Thing per 1 Page"** 원칙으로 화면 분리
2. **검색 중심** 설계 (상단 고정)
3. **점진적 공개** (필요할 때 기능 노출)
4. **친근한 언어** (시스템 용어 제거)
5. **제스처 활용** (스와이프, 롱프레스)
6. **성능 최적화** (필요한 만큼만 로드)

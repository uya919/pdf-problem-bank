# "기타" 사유 직접 입력 UX 계획

> 작성일: 2025-12-11
> 목표: 출결 모달에서 "기타" 선택 시 사유 직접 입력 기능

---

## 1. 현재 흐름 vs 개선 흐름

### 현재 흐름
```
지각/결석 선택 → 사유 칩 표시 → [교통] [병원] [기타] 중 선택 → 완료
                                              ↓
                                    "기타" = 그냥 "기타"로 저장
```

### 개선 흐름
```
지각/결석 선택 → 사유 칩 표시 → [교통] [병원] [기타] 중 선택
                                              ↓
                              [기타] 클릭 시 → 텍스트 입력 필드 확장
                                              ↓
                                        사유 입력 → 완료
```

---

## 2. UX 원칙 적용

### 2.1 Progressive Disclosure (점진적 공개)
- 기본: 사전 정의된 칩만 표시
- 확장: "기타" 클릭 시에만 입력 필드 표시
- **이유**: 대부분의 사용자는 정해진 사유로 충분

### 2.2 Inline Editing (인라인 편집)
- 별도 모달/페이지 없이 현재 위치에서 입력
- 컨텍스트 유지로 빠른 작업 완료
- **토스 스타일**: 복잡한 단계 최소화

### 2.3 Immediate Feedback (즉각적 피드백)
- 입력 중 글자 수 표시
- 입력 완료 시 칩 형태로 변환 표시
- **시각적 확인**: 사용자가 입력 내용 바로 확인

### 2.4 Forgiving Design (관대한 디자인)
- ESC 또는 외부 클릭으로 취소 가능
- 빈 값 입력 시 기본 "기타"로 처리
- **실수 허용**: 쉽게 수정 가능

## 6. 에러 핸들링

### 6.1 입력 검증

| 조건 | 처리 |
|------|------|
| 빈 문자열 | "기타"로 저장 |
| 공백만 입력 | "기타"로 저장 |
| 20자 초과 | 입력 제한 (maxLength) |
| 특수문자 | 허용 (제한 없음) |

### 6.2 상태 복구

- 입력 취소 시: 이전 선택 상태로 복귀
- 새로고침 시: 저장된 값 복원 (세션 단위)

## 7. 접근성 (a11y)

### 7.1 키보드 접근성
- Tab으로 입력 필드 포커스
- Enter/Escape로 확인/취소
- aria-label 추가

### 7.2 스크린 리더
```tsx
<input
  aria-label="지각 사유 직접 입력"
  aria-describedby="char-count"
/>
<span id="char-count" aria-live="polite">
  {text.length}/20
</span>
```

## 8. 구현 계획

### Phase 1: 기본 구현
1. "기타" 클릭 시 입력 필드 토글
2. 입력 → 확인 → 사유 저장
3. ESC/외부 클릭으로 취소

### Phase 2: UX 개선
1. 입력 완료 시 자동 접기
2. 글자 수 제한 표시
3. 애니메이션 추가

### Phase 3: 데이터 연동
1. 사용자 정의 사유 저장 형식 결정
2. 기존 reason 필드와 호환

## 9. 데이터 구조 변경

### 현재
```typescript
interface AttendanceStudent {
  id: string;
  name: string;
  status: 'present' | 'late' | 'absent' | null;
  reason?: string; // "교통", "병원", "기타" 등
}
```

### 변경 후
```typescript
interface AttendanceStudent {
  id: string;
  name: string;
  status: 'present' | 'late' | 'absent' | null;
  reason?: string; // "교통", "병원", "기타: 병원예약" 등
  // 또는
  customReason?: string; // 기타 선택 시 직접 입력한 값
}
```

### 저장 형식 옵션

**옵션 A: reason 필드에 통합**
```json
{ "reason": "기타: 병원예약" }
```
- 장점: 기존 구조 유지
- 단점: 파싱 필요

**옵션 B: 별도 필드 (권장)**
```json
{ "reason": "기타", "customReason": "병원예약" }
```
- 장점: 명확한 분리, 쉬운 조회
- 단점: 필드 추가

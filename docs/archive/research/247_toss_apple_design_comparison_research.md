# 토스 vs 애플 디자인 철학 비교 연구

> 강사 대시보드를 토스와 애플이 각각 설계했다면?

---

## 1. 연구 배경

### 강사의 핵심 워크플로우

```
[출근] → [확인] → [수업] → [기록] → [퇴근]

확인 업무:
├── 공지사항 확인
├── 학원 일정 확인
├── 지난 진도 확인
└── 숙제 확인

기록 업무:
├── 출결 체크
├── 진도 기록
├── 숙제 기록
├── Daily-test 점수
├── Monthly-test 점수
├── 중간/기말 성적
└── 학생 특이사항
```

## 2. 토스의 접근 방식

### 2.1 핵심 철학: Simplicity

> "토스가 생각하는 단순함이란 사용자가 서비스를 이용하기 위해 특별히 알아야 할 것,
> 배워야 할 것 없이 직관적으로 이해할 수 있는 상태입니다."

**토스의 제품 원칙 (PP - Product Principle):**

| 원칙 | 설명 | 강사앱 적용 |
|------|------|------------|
| **Casual Concept** | 전문 용어 → 친숙한 개념 | "진도 기록" (O), "Progress Record" (X) |
| **Minimum Features** | 기능 최소화 | 필수 기능만 남기기 |
| **Less Policy** | 단순한 정책 | 복잡한 조건 제거 |
| **Sleek Experience** | 매끈한 경험 | 모든 터치에 어색함 없이 |

### 2.2 토스의 UX 원칙

**1 thing / 1 page 철학:**
- 한 화면에 한 가지만
- 사용자의 인지 부하 최소화
- 선택지를 줄여 결정 피로 방지

**피크엔드의 법칙:**
- 실패 순간도 부드럽게
- 마지막 인상이 전체 경험을 좌우

### 2.3 토스가 강사 워크플로우를 해결한다면?

```
토스의 해결책: "기록" 중심 설계

현재 문제:
├── 출결/진도/숙제/시험이 각각 분리
├── 수업 → 기록까지 6단계
└── 정보 과부하 (대시보드에 모든 것)

토스의 접근:
├── "기록" 탭으로 통합
├── 수업 카드에서 바로 기록 (2단계)
├── "오늘 할 일" 위젯으로 우선순위
└── Value First: 급한 것 먼저
```

**토스 방식의 워크플로우:**
```
수업 시작 전:
  홈 → "오늘 할 일" 확인 (미완료 3건)

수업 중:
  수업 카드 탭 → [출결] 버튼 → 완료

수업 후:
  같은 카드에서 → [진도] → [숙제] 연속 기록

전체 흐름: 2단계 내 완료
```

## 3. 애플의 접근 방식

### 3.1 핵심 철학: Clarity, Deference, Depth, Consistency

> "Simple can be harder than complex: You have to work hard to get your thinking clean to make it simple."
> — Steve Jobs

**애플의 4가지 설계 원칙:**

| 원칙 | 설명 | 강사앱 적용 |
|------|------|------------|
| **Clarity** | 명확함, 이해하기 쉬움 | 아이콘과 레이블 일관성 |
| **Deference** | 콘텐츠 중심, UI는 배경으로 | 수업 내용이 주인공 |
| **Depth** | 계층감, 시각적 깊이 | 카드, 모달의 레이어 |
| **Consistency** | 일관된 경험 | 어디서든 같은 패턴 |

### 3.2 애플 Reminders 앱에서 배우는 것

> "Apple Reminders manages to strike the perfect balance between simplicity and functionality."

**핵심 특징:**
- 미니멀한 디자인
- 생태계 통합 (Siri, Calendar, Notes)
- Smart Lists: 자동 분류
- 위치/시간/대화 기반 리마인더

### 3.3 애플이 강사 워크플로우를 해결한다면?

```
애플의 해결책: "Context-Aware" 설계

애플의 접근:
├── 위치 기반: 학원 도착 시 오늘 일정 알림
├── 시간 기반: 수업 5분 전 출결 리마인더
├── 컨텍스트 연결: 학생 이름 탭 → 관련 모든 정보
└── Smart Lists: 자동으로 "오늘 할 일" 생성
```

**애플 방식의 워크플로우:**
```
학원 도착:
  자동 알림 → "오늘 수업 3개, 미완료 기록 2건"

수업 시작 5분 전:
  Siri → "중3A반 출결 체크" → 바로 실행

수업 후:
  "Hey Siri, 중3A반 진도 기록"
  → 음성으로 바로 입력

Smart List:
  모든 미완료 항목 자동 수집
```

## 4. 디자인 대안 비교

### 4.1 안 1: 토스 스타일 (기록 중심) ⭐ 1순위

**핵심 아이디어:**
- "기록" 탭 신설
- 수업 카드에서 바로 기록
- "오늘 할 일" 위젯

**장점:**
| 항목 | 설명 |
|------|------|
| 빠른 기록 | 2단계 내 완료 |
| 직관적 | 버튼 보이면 바로 실행 |
| 모바일 최적화 | 한 손 조작 가능 |
| 학습 비용 낮음 | 토스 사용자에게 익숙 |

**단점:**
| 항목 | 설명 |
|------|------|
| 정보 밀도 낮음 | 데스크톱에서 공간 낭비 |
| 개요 파악 어려움 | 한눈에 전체 보기 힘듦 |
| 다중 작업 불리 | 여러 반 비교 어려움 |

**우려 사항:**
- 기존 hyeyum 사용자의 학습 비용
- 출결/진도/숙제가 "기록"으로 통합되면 찾기 어려울 수 있음
- 원장과 강사의 뷰가 너무 달라질 수 있음

**강조하는 워크플로우:**
```
수업 → 즉시 기록
(출결, 진도, 숙제를 연속으로)
```

---

### 4.2 안 2: 애플 스타일 (컨텍스트 중심)

**핵심 아이디어:**
- Smart Lists 자동 분류
- 위치/시간 기반 알림
- 깊이 있는 계층 구조

**장점:**
| 항목 | 설명 |
|------|------|
| 자동화 | 수동 작업 최소화 |
| 생태계 연동 | 캘린더, 알림과 통합 |
| 정보 계층 명확 | Depth로 구조 표현 |
| 검색 강력 | 어디서든 빠르게 찾기 |

**단점:**
| 항목 | 설명 |
|------|------|
| 학습 곡선 | Smart Lists 이해 필요 |
| 복잡성 | 설정 옵션 많음 |
| 개발 비용 높음 | 자동화 로직 구현 |

**네비게이션:**
```
┌─────────────────────────────────┐
│  오늘    예정    전체   Smart   │
└─────────────────────────────────┘
     ↓
  자동 분류된 할 일 목록
```

**강조하는 워크플로우:**
```
컨텍스트 → 자동 제안
(적절한 시점에 적절한 정보)
```

---

### 4.3 안 3: 하이브리드 (토스 + 애플)

**핵심 아이디어:**
- 토스의 간결한 UI
- 애플의 Smart Lists
- 수업 중심 타임라인

**장점:**
| 항목 | 설명 |
|------|------|
| 균형 | 간결함 + 자동화 |
| 유연성 | 상황에 맞게 전환 |
| 친숙함 | 두 생태계 사용자 모두 적응 |

**네비게이션:**
```
┌───────────────────────────────────┐
│  타임라인    할 일    학생    설정  │
└───────────────────────────────────┘
      ↓          ↓
   시간순     Smart List
   수업 뷰    자동 분류
```

**강조하는 워크플로우:**
```
시간 흐름 → 자연스러운 기록
(수업 시간표를 따라가며 기록)
```

## 5. 워크플로우 해결 비교

### 5.1 "진도 기록" 시나리오

| 단계 | 현재 | 토스 (안1) | 애플 (안2) | 하이브리드 (안3) |
|------|------|-----------|-----------|----------------|
| 1 | 홈 | 홈 | "오늘" 탭 | 타임라인 |
| 2 | 반 메뉴 | 수업 카드 탭 | 수업 Smart List | 현재 수업 |
| 3 | 반 선택 | [진도] 버튼 | 진도 항목 탭 | [진도] 버튼 |
| 4 | 탭 전환 | 입력 | 입력 | 입력 |
| 5 | 진도 탭 | - | - | - |
| 6 | + 버튼 | - | - | - |
| 7 | 입력 | - | - | - |
| **총** | **7단계** | **3단계** | **3단계** | **3단계** |

### 5.2 "오늘 할 일 확인" 시나리오

| 방식 | 접근법 | 장점 | 단점 |
|------|--------|------|------|
| **토스** | "오늘 할 일" 위젯 | 한눈에 보임 | 수동 관리 필요 |
| **애플** | Smart List 자동 생성 | 자동화 | 설정 복잡 |
| **하이브리드** | 위젯 + 자동 | 둘 다 | 개발 비용 |

## 6. 결론 및 권장사항

### 6.1 1순위 권장: 토스 스타일 (안 1)

**이유:**
1. hyeyum이 이미 "모바일 우선, 토스 UX 참고"로 설계됨
2. 강사의 핵심 업무가 "기록"이므로 기록 중심 설계 적합
3. 학습 비용 최소화 (기존 토스 사용자 친숙)
4. 개발 비용 합리적

### 6.2 장기적으로 고려: 하이브리드 (안 3)

- 타임라인 기반으로 수업 흐름을 자연스럽게
- Smart Lists로 미완료 항목 자동 수집
- 점진적 마이그레이션 가능

### 6.3 실행 계획

```
Phase 1: 토스 스타일 기본 적용
├── "기록" 탭 신설
├── 수업 카드에 Quick Actions 추가
└── "오늘 할 일" 위젯

Phase 2: 애플 요소 점진 적용
├── Smart Lists (미완료 자동 수집)
├── 시간 기반 리마인더
└── 검색 강화

Phase 3: 하이브리드 완성
├── 타임라인 뷰 옵션
├── 개인화 설정
└── 음성 입력 (선택)
```

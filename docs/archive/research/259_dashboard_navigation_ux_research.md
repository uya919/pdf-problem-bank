# 대시보드 시간 탐색 UX 연구 리포트

> 작성일: 2025-12-10
> 요청: 지난/다음 요일 수업, 과거/미래 공지사항 탐색 방법 연구
> 분석 수준: Deep Research (opus thinkharder)

---

## 1. 핵심 질문

1. **수업 탐색**: 오늘 외 다른 날의 수업을 어떻게 볼 것인가?
2. **공지 탐색**: 과거/미래 공지사항을 어떻게 볼 것인가?
3. **위치 결정**: 대시보드 vs 별도 페이지?

---

## 2. UI/UX 철학 검토

### 2.1 우리의 디자인 원칙 (토스 스타일)

| 원칙 | 의미 | 적용 |
|------|------|------|
| **집중** | 한 화면 = 한 가지 목적 | 대시보드는 "오늘"에 집중 |
| **단순** | 필요한 것만, 필요할 때 | 과거/미래는 필요할 때만 접근 |
| **맥락** | 사용자의 현재 상황 중심 | 지금 해야 할 일 우선 표시 |
| **계층** | 정보의 중요도 구분 | 오늘 > 내일 > 과거 |

### 2.2 대시보드의 본질

```
대시보드 = "오늘, 지금, 해야 할 일"의 허브
```

**핵심 가치:**
- 출근 직후 "오늘 뭐 해야 하지?" → 5초 안에 파악
- 수업 직전 "이 반 뭐였지?" → 3초 안에 접근
- 퇴근 전 "오늘 다 했나?" → 체크리스트 확인

**대시보드가 아닌 것:**
- 아카이브 (과거 기록 저장소)
- 캘린더 (날짜별 전체 일정)
- 검색 도구 (특정 정보 찾기)

## 3. 수업 탐색 분석

### 3.1 사용자 시나리오

| 시나리오 | 빈도 | 긴급도 | 예시 |
|----------|------|--------|------|
| 오늘 수업 확인 | 매우 높음 | 높음 | "다음 수업 뭐지?" |
| 어제 수업 복기 | 중간 | 낮음 | "어제 진도 어디까지 했더라?" |
| 내일 수업 준비 | 중간 | 중간 | "내일 중3A반 시험이네" |
| 지난주 기록 찾기 | 낮음 | 낮음 | "지난주 숙제 뭐였더라?" |
| 다음주 계획 | 낮음 | 중간 | "다음주 시험 기간이니까..." |

### 3.2 구현 옵션 비교

#### Option A: 대시보드 내 날짜 스와이프

```
   [<] 12월 9일 (월) [>]
┌─────────────────────────────┐
│  [중3A반 카드]              │  ← 좌우 스와이프
└─────────────────────────────┘
```

| 장점 | 단점 |
|------|------|
| 직관적 (캐러셀 확장) | 대시보드 복잡해짐 |
| 빠른 접근 | "오늘"의 집중 약화 |
| 익숙한 패턴 | 날짜 많아지면 스와이프 과다 |

**적합도**: ⭐⭐⭐ (3/5) - 간단하지만 철학 위반 가능

---

#### Option B: 하단 네비게이션 "수업" 탭 (별도 페이지)

```
현재: [홈] [수업] [학생] [기록] [더보기]
                ↓
         수업 전용 페이지
┌─────────────────────────────┐
│  📅 12월 2025              │  ← 월 선택
│  [일][월][화][수][목][금][토] │
│   1  2  3  4  5  6  7      │
│      ...                   │
├─────────────────────────────┤
│  12월 9일 (월) 수업         │
│  ├─ 중1C반 15:00 ✓         │
│  ├─ 중3A반 17:00 ✓         │
│  └─ 중2B반 19:00           │
└─────────────────────────────┘
```

| 장점 | 단점 |
|------|------|
| 대시보드 단순 유지 | 추가 탭 이동 필요 |
| 캘린더 뷰 가능 | 개발 비용 높음 |
| 과거/미래 무제한 탐색 | 정보 중복 가능 |
| 역할 분리 명확 | - |

**적합도**: ⭐⭐⭐⭐⭐ (5/5) - 권장

---

#### Option C: 대시보드 + 캘린더 바텀시트

```
대시보드 (오늘)
     ↓ "📅" 버튼 클릭
┌─────────────────────────────┐
│  ← 2025년 12월 →           │  ← 바텀시트
│  [일][월][화][수][목][금][토] │
│   1  2  3  4  5  6  7      │
│  ...                       │
│        [9] ← 선택          │
└─────────────────────────────┘
     ↓ 날짜 선택
대시보드 내용이 해당 날짜로 변경
```

| 장점 | 단점 |
|------|------|
| 빠른 접근 | 대시보드 상태 복잡 |
| 한 화면 유지 | "오늘로 돌아가기" 필요 |
| 캘린더 + 리스트 결합 | 혼란 가능 |

**적합도**: ⭐⭐⭐⭐ (4/5) - 중간 복잡도 허용 시

---

#### Option D: 어제/오늘/내일 탭

```
┌────────────────────────────────┐
│  [어제]  [오늘]  [내일]         │  ← 탭
└────────────────────────────────┘
     ↓ 탭 선택
히어로 카드가 해당 날짜로 변경
```

| 장점 | 단점 |
|------|------|
| 매우 단순 | 3일만 가능 |
| 직관적 | 지난주/다음주 불가 |
| 구현 쉬움 | 확장성 없음 |

**적합도**: ⭐⭐⭐ (3/5) - MVP로는 가능

---

### 3.3 수업 탐색 결론

**권장: Option B (수업 탭 분리)**

```
[홈] = 오늘의 허브 (히어로 카드 스와이프)
[수업] = 날짜별 수업 탐색 (캘린더 + 리스트)
```

**이유:**
1. 대시보드의 "오늘" 집중 유지
2. 과거/미래 무제한 탐색 가능
3. 역할 분리로 인지 부하 감소
4. 이미 하단 네비에 "수업" 탭 존재

## 4. 공지사항 탐색 분석

### 4.1 공지의 특성

| 특성 | 설명 |
|------|------|
| **시간 민감성** | 결석 알림은 오늘, 시험 알림은 일주일 전 |
| **우선순위** | 긴급한 것 vs 참고용 |
| **상태** | 읽음/안읽음, 처리완료/미완료 |
| **수명** | 일회성 vs 반복 (매주 회의) |

### 4.2 사용자 시나리오

| 시나리오 | 빈도 | 예시 |
|----------|------|------|
| 오늘 새 공지 확인 | 매우 높음 | "새로운 알림 있나?" |
| 지난 공지 복기 | 중간 | "어제 학부모가 뭐라고 했더라?" |
| 예정된 일정 확인 | 중간 | "다음주 시험 언제더라?" |
| 공지 검색 | 낮음 | "김민수 관련 연락 찾기" |

### 4.3 구현 옵션 비교

#### Option A: 대시보드 드롭박스 + "전체보기" 링크

```
현재 대시보드:
┌─────────────────────────────┐
│  🔔 공지사항 (3)    [전체보기]│
│  ├─ 김민수(중3A) 결석       │
│  ├─ 12/11(수) 전체 회의     │
│  └─ 중3A 내일 시험          │
└─────────────────────────────┘
            ↓ "전체보기" 클릭
┌─────────────────────────────┐
│  ← 공지사항                 │  ← 새 페이지 or 바텀시트
│                             │
│  [전체] [안읽음] [긴급]      │  ← 필터 탭
│                             │
│  오늘 ──────────────────    │
│  • 김민수(중3A) 결석        │
│  • 12/11(수) 전체 회의      │
│                             │
│  어제 ──────────────────    │
│  • 교재 입고 완료           │
│                             │
│  지난주 ────────────────    │
│  • 12월 학원 일정 공유      │
└─────────────────────────────┘
```

| 장점 | 단점 |
|------|------|
| 대시보드 단순 유지 | 한 단계 더 들어가야 함 |
| 전체 공지 무제한 탐색 | 개발 필요 |
| 필터/검색 가능 | - |

**적합도**: ⭐⭐⭐⭐⭐ (5/5) - 권장

---

#### Option B: 공지 스와이프 캐러셀

```
┌─────────────────────────────┐
│  🔔 공지사항                │
│ ← [카드1] [카드2] [카드3] → │  ← 스와이프
└─────────────────────────────┘
```

| 장점 | 단점 |
|------|------|
| 빠른 훑어보기 | 카드가 많으면 힘듦 |
| 시각적 재미 | 필터 불가 |

**적합도**: ⭐⭐ (2/5) - 공지는 리스트가 더 적합

---

#### Option C: 하단 네비에 "알림" 탭 추가

```
현재: [홈] [수업] [학생] [기록] [더보기]
변경: [홈] [수업] [학생] [알림] [더보기]
                         ↑ 기록 대체
```

| 장점 | 단점 |
|------|------|
| 전용 공간 확보 | 탭 변경 필요 |
| 푸시 알림 연계 용이 | "기록" 탭 위치 조정 |

**적합도**: ⭐⭐⭐⭐ (4/5) - 알림이 중요하면 고려

---

### 4.4 공지 탐색 결론

**권장: Option A (드롭박스 + 전체보기)**

```
대시보드: 오늘의 중요 공지 3~5개
전체보기: 날짜별/필터별 전체 공지
```

**이유:**
1. 대시보드는 "핵심"만 표시
2. "전체보기"로 아카이브 접근
3. 기존 레이아웃 유지 가능

## 5. 종합 아키텍처 제안

### 5.1 페이지 구조

```
┌─────────────────────────────────────────────────┐
│                     앱 구조                      │
├─────────────────────────────────────────────────┤
│                                                 │
│  [홈] ─────────── 대시보드 (오늘 중심)          │
│         │                                       │
│         ├─ 히어로 캐러셀 (오늘 수업들)          │
│         ├─ 공지 드롭박스 (오늘 공지)            │
│         ├─ 할 일 리스트                        │
│         └─ 타임라인 (오늘 일정)                 │
│                                                 │
│  [수업] ─────────── 수업 관리 페이지            │
│         │                                       │
│         ├─ 캘린더 뷰 (월별)                    │
│         ├─ 날짜 선택 → 해당 날 수업 리스트     │
│         └─ 수업 클릭 → 상세/출결/진도          │
│                                                 │
│  [학생] ─────────── 학생 관리 페이지            │
│                                                 │
│  [기록] ─────────── 진도/출결 기록              │
│         │                                       │
│         ├─ 반별 진도 현황                      │
│         └─ 출결 통계                           │
│                                                 │
│  [더보기] ────────── 설정 & 기타                │
│         │                                       │
│         ├─ 공지사항 전체보기 ← 여기!           │
│         ├─ 프로필 설정                         │
│         └─ 알림 설정                           │
│                                                 │
└─────────────────────────────────────────────────┘
```

## 7. 대안 검토: 대시보드에 모두 넣으면?

### 7.1 최대주의 대시보드

```
┌─────────────────────────────────────────┐
│  [어제] [오늘] [내일]  ← 날짜 탭        │
├─────────────────────────────────────────┤
│  히어로 캐러셀                          │
├─────────────────────────────────────────┤
│  🔔 공지사항 [과거] [오늘] [예정]       │  ← 공지 탭
├─────────────────────────────────────────┤
│  📋 할 일                              │
├─────────────────────────────────────────┤
│  📅 일정                               │
└─────────────────────────────────────────┘
```

### 7.2 문제점

| 문제 | 설명 |
|------|------|
| **인지 과부하** | 탭이 너무 많음 (날짜 탭 + 공지 탭) |
| **역할 모호** | 대시보드? 캘린더? 공지함? |
| **유지보수** | 상태 관리 복잡 (어느 날짜의 어느 공지?) |
| **성능** | 모든 날짜 데이터 로드 필요 |

### 7.3 결론

> **"대시보드는 스위스 군용 칼이 아니라 예리한 메스여야 한다"**

대시보드에 모든 기능을 넣으면 편리해 보이지만:
- 핵심 목적 ("오늘 뭐 해야 하지?") 흐려짐
- 사용자 혼란 증가
- 개발/유지보수 복잡

## 8. 최종 권장안

### 8.1 원칙

```
대시보드 = 오늘의 "허브" (입구)
다른 탭 = 깊은 탐색 "스포크" (가지)
```

### 8.2 구현 방향

| 기능 | 위치 | 이유 |
|------|------|------|
| 오늘 수업 | 대시보드 히어로 | 가장 중요, 즉시 접근 |
| 다른 날 수업 | [수업] 탭 | 캘린더 필요, 역할 분리 |
| 오늘 공지 | 대시보드 드롭박스 | 빠른 확인 |
| 전체 공지 | [더보기] > 공지사항 | 아카이브 접근 |

### 8.3 사용자 흐름 시뮬레이션

**아침 출근:**

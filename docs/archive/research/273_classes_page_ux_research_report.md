## 2. 문제점 분석

### 2.1 기능 중복

| 기능 | 대시보드 | 수업 페이지 |
|------|----------|-------------|
| 오늘 수업 보기 | ✅ 캐러셀 | ✅ 리스트 |
| 출결 체크 | ✅ 버튼 | ✅ 버튼 |
| 진도 기록 | ✅ 버튼 | ❌ (없음) |
| 수업 상세 | ❌ | ✅ 버튼 |
| 요일별 조회 | ❌ | ✅ 탭 |

**문제**: 같은 "오늘 수업"을 두 곳에서 다르게 보여줌

### 2.2 사용자 여정 비효율

```
시나리오: 선생님이 "중3A반" 진도를 확인하고 싶음

현재 흐름:
[대시보드] → 캐러셀 스와이프 → 중3A반 찾기 → [진도] 버튼
    또는
[수업 탭] → 요일 탭 클릭 → 스크롤 → 수업 카드 찾기 → ???(진도 없음)

문제점:
1. "반" 중심이 아닌 "시간" 중심 정렬
2. 수업 페이지에서 진도 기록 불가
3. 어디서 뭘 해야 하는지 혼란
```

### 2.3 토스 UI/UX 철학 위반

| 원칙 | 현재 상태 | 문제 |
|------|-----------|------|
| **집중** | 두 페이지가 비슷한 역할 | 사용자 집중 분산 |
| **단순** | 중복 UI 요소 | 불필요한 복잡성 |
| **즉각적** | 페이지 이동 필요 | 즉각성 저하 |
| **일관성** | 대시보드=카드, 수업=리스트 | 패턴 불일치 |

## 3. 사용자 제안 분석

> "최상단에 담당하는 반을 탭할 수 있고 세부 내용이 펼쳐지면 좋겠다"

### 3.1 제안의 핵심 통찰

1. **"반 중심" 사고**
   - 선생님의 멘탈 모델: "나는 중3A반, 고1B반을 담당한다"
   - 현재 시스템: "월요일에 뭐가 있지?" (시간 중심)

2. **Progressive Disclosure**
   - 처음엔 반 이름만 (요약)
   - 탭하면 상세 정보 (펼침)
   - 필요한 만큼만 보여주기


## 4. 비교 분석

### 4.1 정보 구조 비교

| 구조 | 현재 (요일 중심) | 제안 (반 중심) |
|------|------------------|----------------|
| 1차 분류 | 요일 (월~일) | 담당 반 |
| 2차 분류 | 시간 순서 | 정보 유형 |
| 접근 방식 | "오늘 뭐하지?" | "이 반은 어떻지?" |
| 멘탈 모델 | 캘린더 | 반 관리 |

### 4.2 사용 시나리오 비교

**시나리오 1: 학부모 전화 "우리 애 진도가 어떻게 되나요?"**

```
현재:
1. 학생 이름 → 어느 반인지 기억해야 함
2. 수업 탭 → 요일 탭 클릭 → 스크롤 → 반 찾기
3. 진도 정보가 없음 → 대시보드로 이동? 기록 탭?

제안:
1. 수업 탭 → 해당 반 탭 클릭
2. 진도 섹션에서 즉시 확인
3. 바로 답변 가능
```

**시나리오 2: 수업 시작 전 출결 체크**

```
현재:
1. 대시보드 → 캐러셀에서 해당 반 찾기 → 출결 버튼
   또는
2. 수업 탭 → 오늘 요일 → 해당 수업 카드 → 출결체크 버튼

제안:
1. 수업 탭 → 해당 반 탭 (이미 선택되어 있을 수 있음)
2. 일정 섹션에서 오늘 수업 확인 → 출결 버튼
```

### 4.3 장단점 비교

| 측면 | 현재 (요일 중심) | 제안 (반 중심) |
|------|------------------|----------------|
| **장점** | 하루 일정 파악 용이 | 반별 관리 용이 |
| | 대시보드와 연계 | 정보 집중도 높음 |
| **단점** | 반 정보 분산 | 하루 전체 일정 파악 어려움 |
| | 기능 중복 | 새로운 학습 필요 |

## 5. 제안: 하이브리드 접근

### 5.1 역할 재정의

| 페이지 | 역할 | 핵심 질문 |
|--------|------|-----------|
| **대시보드** | 오늘의 일정 + 할 일 | "오늘 뭐하지?" |
| **수업 페이지** | 반별 상세 관리 | "이 반은 어떻지?" |

### 5.2 대시보드 (유지)

```
- 오늘 수업 캐러셀 (요약)
- 오늘 할 일 뱃지 (행동 유도)
- 빠른 액션 (출결, 진도)

역할: 오늘 하루의 "워크플로우 허브"
```

### 5.3 수업 페이지 (개선)

```
- 담당 반 탭 (반 중심)
- 반별 상세 정보 (펼침)
- 히스토리 및 관리 기능

역할: 반별 "정보 센터"
```

```
                         │
```

### 6.3 인터랙션 플로우

```
1. 반 탭 클릭
   └→ 해당 반 정보 로드
   └→ 모든 섹션 기본 펼침 상태

2. 섹션 헤더 클릭 (▼)
   └→ 해당 섹션 토글 (접기/펼치기)
   └→ 다른 섹션은 유지

3. [출결체크] 버튼
   └→ AttendanceModal 열림
   └→ 저장 시 상태 업데이트

4. [진도기록] 버튼
   └→ ProgressModal 열림
   └→ 저장 시 진도 섹션 업데이트

5. [상세보기] / [전체보기]
   └→ 상세 페이지로 이동 또는 모달

6. 학생 아바타 클릭
   └→ 학생 상세 정보 (성적, 출결 히스토리)
```

## 7. 토스 철학 적용 검증

### 7.1 집중 (Focus)

| 항목 | 현재 | 개선 후 |
|------|------|---------|
| 한 화면 목적 | 요일별 수업 조회 | 반별 종합 관리 |
| 주의 분산 | 여러 반 카드 나열 | 선택된 반에 집중 |
| 평가 | ⚠️ 중간 | ✅ 좋음 |

### 7.2 단순 (Simple)

| 항목 | 현재 | 개선 후 |
|------|------|---------|
| 정보 계층 | 평면적 (모든 카드 동일) | 계층적 (탭 → 섹션) |
| 시각적 복잡도 | 많은 카드 | 하나의 상세 뷰 |
| 평가 | ⚠️ 중간 | ✅ 좋음 |

### 7.3 즉각적 (Immediate)

| 항목 | 현재 | 개선 후 |
|------|------|---------|
| 반 정보 접근 | 스크롤 필요 | 탭 한 번 |
| 액션 버튼 | 카드마다 존재 | 해당 섹션에 집중 |
| 평가 | ⚠️ 중간 | ✅ 좋음 |

### 7.4 일관성 (Consistent)

| 항목 | 현재 | 개선 후 |
|------|------|---------|
| 대시보드와의 관계 | 중복/혼란 | 역할 분리 |
| UI 패턴 | 리스트 | 아코디언 (일관된 패턴) |
| 평가 | ❌ 나쁨 | ✅ 좋음 |

## 8. 구현 권장사항

### 8.1 Phase 2 개선 (수업 페이지 리디자인)

1. **ClassTabBar 컴포넌트**: 담당 반 탭 바
2. **ClassDetailView 컴포넌트**: 반별 상세 뷰
3. **AccordionSection 컴포넌트**: 펼침/접기 섹션
4. **기존 모달 재사용**: AttendanceModal, ProgressModal

### 8.2 데이터 구조

```typescript
interface MyClass {
  id: string;
  name: string;           // "중3A반"
  subject: string;        // "수학"
  studentCount: number;   // 8
  schedules: Schedule[];  // 월/수/금 일정
  recentProgress: Progress[];
  students: Student[];
  currentHomework: Homework | null;
}

interface Schedule {
  dayOfWeek: '월' | '화' | '수' | '목' | '금' | '토' | '일';
  startTime: string;
  endTime: string;
  isToday: boolean;
}
```

### 8.3 마이그레이션 전략

```
Step 1: 새 컴포넌트 개발 (기존 페이지 유지)
Step 2: A/B 토글로 테스트
Step 3: 피드백 수렴
Step 4: 기존 요일 탭 방식 제거
```

## 9. 결론

### 9.1 핵심 인사이트

1. **기능 중복은 UX 혼란의 원인**
   - 대시보드와 수업 페이지의 역할이 불명확
   - 같은 정보를 다른 방식으로 표시

2. **사용자의 멘탈 모델 반영 필요**
   - 선생님은 "반" 단위로 사고
   - 시스템은 "요일/시간" 단위로 설계

3. **Progressive Disclosure의 가치**
   - 처음엔 요약 (반 탭)
   - 필요할 때 상세 (섹션 펼침)
   - 인지 부하 감소

### 9.2 최종 권장안

| 페이지 | 역할 | 핵심 UX |
|--------|------|---------|
| **대시보드** | 오늘의 워크플로우 | 시간 중심, 할 일 중심 |
| **수업 페이지** | 반별 정보 센터 | 반 중심, 상세 정보 |

**수업 페이지 개선 방향**:
- 상단에 담당 반 탭
- 선택 시 해당 반의 모든 정보 표시
- 아코디언 섹션으로 정보 그룹화
- 대시보드에서 "상세보기" 클릭 시 해당 반으로 이동

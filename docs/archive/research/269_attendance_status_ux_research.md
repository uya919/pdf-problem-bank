# 출결 상태 옵션 UX 연구

> 작성일: 2025-12-11
> 목표: 출석/결석 외 지각, 조퇴 등 상세 상태 옵션의 UX 설계

---

## 1. 현재 구현 vs 목업 비교

| 항목 | 현재 구현 | 초기 목업 |
|------|----------|----------|
| 상태 옵션 | 출석, 결석 | 출석, 결석, 지각, 조퇴 |
| 인터랙션 | 토글 스위치 | 탭 → 상태 선택 |
| 사유 입력 | 없음 | 결석/지각 시 사유 입력 |

### 현재 구현의 장단점

**장점**:
- 빠른 입력 (탭 1회)
- 직관적 토글
- UI 단순함

**단점**:
- 지각/조퇴 구분 불가
- 세부 사유 기록 불가
- 통계 분석 제한적

## 2. 학원 출결 관리 실제 니즈

### 2.1 출결 상태 분류

| 상태 | 설명 | 빈도 |
|------|------|------|
| 출석 | 정시 출석 | 매우 높음 (90%+) |
| 결석 | 수업 불참 | 낮음 |
| 지각 | 수업 시작 후 도착 | 가끔 |
| 조퇴 | 수업 종료 전 퇴장 | 드물게 |
| 보강 | 결석 후 보충 수업 | 드물게 |

### 2.2 사유 필요성

```
결석 사유:
- 병원/병결
- 가족 행사
- 학교 행사
- 기타

지각 사유:
- 교통 문제
- 이전 수업 연장
- 개인 사정
```

### 2.3 학원 관리자 요구사항

1. **빠른 입력**: 대부분 출석이므로 빠른 처리 필요
2. **예외 기록**: 결석/지각 시 사유 기록 (학부모 문의 대비)
3. **통계**: 월별 출결 현황, 지각 빈도 등
4. **알림**: 결석 시 학부모 알림 (선택적)

## 3. UX 패턴 분석

### 3.1 패턴 A: 단순 토글 (현재)

```
[출석] [결석]
```

**특징**:
- 2가지 상태만 구분
- 한 번의 탭으로 전환
- 상세 정보 없음

**적합한 경우**:
- 빠른 출결 체크가 최우선
- 지각/조퇴 구분이 불필요한 경우
- 사유 기록이 별도 시스템에서 관리되는 경우

### 3.2 패턴 B: 4상태 토글

```
[출석] [지각] [조퇴] [결석]
```

**특징**:
- 4가지 상태 구분
- 한 번의 탭으로 선택
- 상세 정보 없음

**문제점**:
- 버튼이 4개라 공간 차지
- 작은 화면에서 터치 영역 좁음
- 지각/조퇴 선택 시 시간 정보 필요할 수 있음

### 3.3 패턴 C: 탭 후 확장 (권장)

```
기본: [출석 ✓] ← 기본값

탭 시:
┌──────────────────────────────┐
│  [출석]  [지각]  [조퇴]  [결석]  │
│  사유: _______________        │
└──────────────────────────────┘
```

**특징**:
- 기본값은 출석 (빠른 처리)
- 탭하면 상세 옵션 확장
- 지각/결석 선택 시 사유 입력 가능

**장점**:
- Progressive Disclosure (점진적 공개)
- 대부분의 경우 (출석) 빠르게 처리
- 예외 케이스만 상세 입력

### 3.4 패턴 D: 스와이프 제스처

```
← 스와이프: 결석
→ 스와이프: 출석
길게 누르기: 상세 옵션
```

**특징**:
- 모바일 친화적
- 빠른 처리 가능
- 학습 비용 있음

## 4. 토스 스타일 적용

### 4.1 핵심 원칙

1. **기본값 제공**: 가장 흔한 케이스(출석)를 기본값으로
2. **점진적 공개**: 필요할 때만 상세 옵션 표시
3. **즉각적 피드백**: 상태 변경 시 바로 시각적 피드백
4. **원탭 완료**: 대부분의 경우 한 번 탭으로 완료

### 4.2 권장 디자인

```
┌─────────────────────────────────────────────────┐
│ 김민수                              [출석 ✓] │
└─────────────────────────────────────────────────┘

↓ 탭 시 확장

┌─────────────────────────────────────────────────┐
│ 김민수                                         │
│                                                 │
│   [출석]   [지각]   [조퇴]   [결석]             │
│      ✓                                          │
│                                                 │
│ ─────────────────────────────────────────────── │
│ 사유 (선택): [병원] [교통] [학교행사] [기타]    │
└─────────────────────────────────────────────────┘
```

### 4.3 상태별 색상

| 상태 | 배경색 | 텍스트 | 아이콘 |
|------|--------|--------|--------|
| 출석 | `#E8F5E9` | `#2E7D32` | ✓ |
| 지각 | `#FFF3E0` | `#E65100` | ⏰ |
| 조퇴 | `#E3F2FD` | `#1565C0` | ← |
| 결석 | `#FFEBEE` | `#C62828` | ✕ |

## 5. 인터랙션 플로우

### 5.1 기본 플로우 (출석)

```
1. 학생 행 탭
2. [출석] 버튼 활성화 (이미 선택됨)
3. 다음 학생으로 자동 포커스 (선택적)
```

### 5.2 지각 플로우

```
1. 학생 행 탭
2. [지각] 버튼 탭
3. 사유 칩 표시: [교통] [이전수업] [개인사정]
4. 사유 선택 (또는 스킵)
5. 완료
```

### 5.3 결석 플로우

```
1. 학생 행 탭
2. [결석] 버튼 탭
3. 사유 칩 표시: [병원] [가족행사] [학교행사] [기타]
4. 사유 선택 (권장)
5. [학부모 알림] 버튼 표시 (선택적)
6. 완료
```

## 6. 컴팩트 디자인 옵션

### 6.1 Option A: 인라인 확장

```
┌─────────────────────────────────────────────────┐
│ 김민수                              [출석 ✓]   │
├─────────────────────────────────────────────────┤
│ 이영희                              [출석 ✓]   │
├─ 확장됨 ────────────────────────────────────────┤
│ 박철수                                          │
│  [출석] [지각] [조퇴] [결석]                    │
│   사유: [병원]                      [완료]      │
├─────────────────────────────────────────────────┤
│ 최지원                              [미확인]    │
└─────────────────────────────────────────────────┘
```

**장점**: 리스트 컨텍스트 유지
**단점**: 확장 시 리스트 높이 변경

### 6.2 Option B: 바텀시트 (상세 입력용)

```
학생 탭 → 바텀시트 오픈

┌─────────────────────────────────────────────────┐
│ ← 박철수 출결 체크                              │
├─────────────────────────────────────────────────┤
│                                                 │
│   ┌─────┐  ┌─────┐  ┌─────┐  ┌─────┐           │
│   │ 출석 │  │ 지각 │  │ 조퇴 │  │ 결석 │           │
│   │  ✓  │  │ ⏰  │  │  ←  │  │  ✕  │           │
│   └─────┘  └─────┘  └─────┘  └─────┘           │
│                                                 │
│   사유 선택:                                    │
│   [병원] [교통] [학교행사] [기타]               │
│                                                 │
│   ┌─────────────────────────────────────────┐  │
│   │              [확인]                      │  │
│   └─────────────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
```

**장점**: 충분한 입력 공간
**단점**: 한 명씩 처리 (느림)

### 6.3 Option C: 하이브리드 (권장)

```
기본 모드: 토글 [출석][결석]
상세 모드: 행 길게 누르기 → 바텀시트
```

**장점**:
- 빠른 처리 (기본 모드)
- 상세 입력 가능 (상세 모드)
- 사용자 선택권

## 7. 구현 제안

### 7.1 Phase 1: 기본 확장

현재 `[출석][결석]` → `[출석][지각][결석]` 3단계

```tsx
<div className="toggle-group">
  <button className={status === 'present' ? 'active' : ''}>출석</button>
  <button className={status === 'late' ? 'active' : ''}>지각</button>
  <button className={status === 'absent' ? 'active' : ''}>결석</button>
</div>
```

### 7.2 Phase 2: 사유 추가

지각/결석 선택 시 사유 칩 표시

```tsx
{(status === 'late' || status === 'absent') && (
  <div className="reason-chips">
    <button onClick={() => setReason('병원')}>병원</button>
    <button onClick={() => setReason('교통')}>교통</button>
    <button onClick={() => setReason('기타')}>기타</button>
  </div>
)}
```

### 7.3 Phase 3: 조퇴 추가 (선택적)

필요 시 조퇴 상태 추가

## 8. 결론 및 권장사항

### 8.1 권장 구현 순서

| 우선순위 | 기능 | 복잡도 |
|---------|------|--------|
| 1 | 지각 상태 추가 | 낮음 |
| 2 | 사유 칩 (인라인) | 중간 |
| 3 | 조퇴 상태 추가 | 낮음 |
| 4 | 상세 바텀시트 | 높음 |

### 8.2 최종 권장 디자인

```
기본 UI:
┌─────────────────────────────────────────────────┐
│ 김민수              [출석] [지각] [결석]        │
│                        ✓                       │
└─────────────────────────────────────────────────┘

지각/결석 선택 시:
┌─────────────────────────────────────────────────┐
│ 박철수              [출석] [지각] [결석]        │
│                               ✓                │
│ └ 사유: [병원] [교통] [기타]                    │
└─────────────────────────────────────────────────┘
```

### 8.3 토스 UX 원칙 준수

1. **간결함**: 3개 상태 (출석/지각/결석)로 충분
2. **빠른 처리**: 한 번 탭으로 상태 선택
3. **선택적 상세**: 사유는 필요할 때만 입력
4. **즉각적 피드백**: 선택 시 색상 변화

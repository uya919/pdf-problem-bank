# 히어로 캐러셀 자동 날짜 이동 구현 가능성 연구

> 마지막 수업 이후 스와이프 시 중간 카드 없이 바로 다음 날짜로 이동

**작성일**: 2025-12-12
**요청**: 수업 3개 → 다음 스와이프 → (날짜 카드 없이) 바로 다음날 이동

---

## 1. 현재 구현 방식 (Option A: 경계 카드)

```
[← 12/11] → [수업1] → [수업2] → [수업3] → [12/13 →]
                                              ↑
                                         탭해야 이동
```

**장점**:
- 사용자가 날짜 이동 의도를 명확히 확인 가능
- 실수로 날짜가 바뀌는 것 방지
- Embla Carousel 기본 동작 활용

**단점**:
- 추가 스와이프 + 탭 필요 (2단계)
- 날짜 이동 카드가 "빈 화면"처럼 느껴질 수 있음

---

## 2. 요청된 방식 (Option B: 자동 이동)

```
[수업1] → [수업2] → [수업3] → (스와이프) → 바로 12/13 날짜 로드
```

**장점**:
- 더 빠른 날짜 탐색 (1단계)
- 날짜 카드 없이 깔끔한 UX
- 자연스러운 "끝없는 스크롤" 느낌

---

## 3. 구현 가능성 분석

### 3.1 기술적 구현 방법

```typescript
// HeroCarousel.tsx - 슬라이드 변경 감지
useEffect(() => {
  if (!emblaApi) return;

  const onSettle = () => {
    const index = emblaApi.selectedScrollSnap();
    const totalSlides = emblaApi.scrollSnapList().length;

    // 마지막 슬라이드에서 계속 스와이프 감지
    if (index === totalSlides - 1 && canGoNext) {
      // 스와이프 방향 감지 후 자동 이동
      onNextDay?.();
    }

    // 첫 슬라이드에서 역방향 스와이프 감지
    if (index === 0 && canGoPrev) {
      onPrevDay?.();
    }
  };

  emblaApi.on('settle', onSettle);
  return () => emblaApi.off('settle', onSettle);
}, [emblaApi, onNextDay, onPrevDay]);
```

### 3.2 구현 난이도: **중간 (6/10)**

| 항목 | 난이도 | 설명 |
|------|--------|------|
| 스와이프 끝 감지 | 쉬움 | Embla `settle` 이벤트 활용 |
| 방향 감지 | 중간 | 스와이프 방향 vs 위치 판단 필요 |
| 날짜 전환 애니메이션 | 어려움 | 자연스러운 전환 효과 구현 |
| 상태 초기화 | 중간 | 새 날짜 로드 후 시작 위치 설정 |

## 4. 우려되는 점

### 4.1 UX 문제

| 우려 사항 | 심각도 | 설명 |
|-----------|--------|------|
| **실수로 날짜 변경** | 높음 | 마지막 수업 보다가 조금만 스와이프해도 날짜가 바뀜 |
| **되돌리기 어려움** | 중간 | 바뀐 날짜에서 원래 날짜로 돌아가려면 반대로 스와이프 |
| **현재 날짜 인지 혼란** | 중간 | 날짜가 자동으로 바뀌면 사용자가 "오늘"인지 헷갈릴 수 있음 |
| **로딩 지연** | 낮음 | 날짜 변경 시 데이터 로드 대기 시간 |

### 4.2 기술적 문제

| 문제 | 설명 | 해결책 |
|------|------|--------|
| **스와이프 의도 판단** | "끝까지 봄" vs "다음 날로 이동" 구분 어려움 | 스와이프 거리 임계값 설정 |
| **연속 스와이프** | 빠르게 여러 번 스와이프 시 날짜가 계속 바뀜 | debounce 적용 |
| **무한 루프 방지** | 날짜 변경 → 캐러셀 재렌더링 → 또 이동 | 상태 플래그로 제어 |
| **애니메이션 끊김** | 날짜 변경 시 캐러셀이 갑자기 리셋됨 | fade-out/fade-in 전환 |

### 4.3 사용자 시나리오별 문제

**시나리오 1: 마지막 수업 자세히 보기**
```
[수업3] 카드에서 출결 버튼 누르려고 살짝 스와이프
→ 의도치 않게 다음 날로 이동
→ 사용자 혼란
```

**시나리오 2: 오늘 수업 확인 후 복귀**
```
12/12 → (스와이프) → 12/13 → (스와이프) → 12/14
→ 오늘로 돌아가려면 2번 역스와이프 필요
→ "오늘" 버튼 필요할 수도
```

## 5. 대안 제안

### 5.1 Option B-1: 과스와이프 트리거 (권장)

마지막 카드에서 **추가로 크게 스와이프**해야만 날짜 이동

```
[수업3] → (살짝 스와이프) → 아무 일 없음
[수업3] → (크게 스와이프, 150px+) → 다음 날로 이동
```

**구현**:
```typescript
const SWIPE_THRESHOLD = 150; // px

emblaApi.on('scroll', () => {
  const progress = emblaApi.scrollProgress();
  if (progress > 1.3) { // 끝을 넘어서 30% 더 스와이프
    onNextDay?.();
  }
});
```

**장점**: 의도적 스와이프만 인식, 실수 방지

### 5.2 Option B-2: 길게 누르기 + 스와이프

마지막 카드에서 **길게 누른 상태로 스와이프**

```
[수업3] → (일반 스와이프) → 아무 일 없음
[수업3] → (0.5초 홀드 + 스와이프) → 다음 날로 이동
```

**장점**: 매우 명확한 의도 표현
**단점**: 발견성 낮음, 학습 필요

### 5.3 Option B-3: 엣지 힌트 + 자동 이동

마지막 카드에서 스와이프 시 **힌트 표시 후 자동 이동**

```
[수업3] → (스와이프) → "12/13으로 이동" 힌트 표시 (0.5초)
                      → 자동으로 날짜 변경
```

**장점**: 사용자에게 피드백 제공
**단점**: 지연 시간 추가

### 5.4 Option C: 하이브리드 (현재 + 개선)

현재 방식 유지하되, 날짜 카드에서 **자동 이동 옵션 추가**

```
[수업3] → [12/13 카드] → (1초 후 자동 이동) 또는 (탭하면 즉시 이동)
```

```typescript
// 날짜 카드에 도달 후 1초 뒤 자동 이동
useEffect(() => {
  if (isOnDayNavCard) {
    const timer = setTimeout(() => onNextDay?.(), 1000);
    return () => clearTimeout(timer);
  }
}, [isOnDayNavCard]);
```

## 6. 구현 권장안

### 1순위: Option B-1 (과스와이프 트리거)

- **구현 복잡도**: 중간
- **UX 안정성**: 높음
- **실수 방지**: 높음

```typescript
// 핵심 로직
const handleOverscroll = useCallback(() => {
  if (!emblaApi) return;

  const { limit, target } = emblaApi.internalEngine();
  const overscroll = target.get() - limit.max;

  if (overscroll > 150 && onNextDay) {
    onNextDay();
  }
}, [emblaApi, onNextDay]);
```

### 2순위: Option C (하이브리드)

현재 구현을 유지하면서 날짜 카드에 자동 이동 타이머 추가

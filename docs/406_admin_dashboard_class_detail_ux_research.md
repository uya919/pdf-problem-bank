# Admin PC 대시보드 수업 상세 정보 UX 연구리포트

**문서 번호**: 406
**작성일**: 2025-12-20
**요청**: 대시보드에서 수업별 상세 정보(지난 진도, 지난 숙제, 오늘 진도, 오늘 숙제, 특이사항) 표시 UX 연구

---

## 1. 현재 상태 분석

### 1.1 현재 대시보드 구조

```
┌─────────────────────────────────────────────────────────┐
│  주간 캘린더 (날짜 선택)                                   │
├─────────────────────────────────────────────────────────┤
│  현재 진행 중 (14:00~16:00) ← 삭제 예정                    │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐            │
│  │ 중1A반  │ │ 중2B반  │ │ 고1A반  │ │ ...    │            │
│  │ 상 · 5명│ │ 중 · 4명│ │ 상 · 6명│ │        │            │
│  │ 출결 확인중│         │          │           │            │
│  └────────┘ └────────┘ └────────┘ └────────┘            │
├─────────────────────────────────────────────────────────┤
│  오늘 수업 일정                                           │
│  14:00 ~16:00  │ 중1A · 김선생 │ 중2B · 박선생 │ ...       │
│  16:00 ~18:00  │ 고1A · 이선생 │ 고2B · 최선생 │ ...       │
│  18:00 ~20:00  │ 중3A · 정선생 │                          │
└─────────────────────────────────────────────────────────┘
```

### 1.2 현재 문제점

| 문제 | 설명 |
|------|------|
| **정보 부족** | 반 이름과 담당 강사만 표시, 수업 내용 파악 불가 |
| **진도 확인 불가** | 지난 수업에서 어디까지 했는지 알 수 없음 |
| **숙제 현황 없음** | 학생들이 숙제를 했는지 확인 불가 |
| **컨텍스트 부재** | 이전 수업과의 연결성 없음 |
| **중복 섹션** | "현재 진행 중"이 "오늘 수업 일정"과 중복 |

## 2. 사용자 니즈 분석

### 2.1 원장/관리자의 핵심 질문

대시보드를 볼 때 원장이 알고 싶은 것:

1. **"오늘 뭐 하지?"** → 오늘 진도 예정
2. **"지난번에 뭐 했지?"** → 지난 진도
3. **"숙제 다 했나?"** → 지난 숙제 제출 현황
4. **"오늘 숙제는?"** → 오늘 내줄 숙제
5. **"특이사항 있나?"** → 결석, 보충, 상담 등

### 2.2 정보 우선순위 (Information Hierarchy)

```
[Critical] 오늘 해야 할 것 (오늘 진도)
    ↓
[High] 오늘 확인할 것 (지난 숙제 제출 현황)
    ↓
[Medium] 컨텍스트 (지난 진도 - 어디서 이어가는지)
    ↓
[Low] 계획 (오늘 숙제 - 수업 후 결정)
    ↓
[Optional] 특이사항 (있을 때만)
```

## 3. UI/UX 디자인 철학

### 3.1 Progressive Disclosure (점진적 노출)

> "사용자에게 필요한 정보만 적시에 제공한다"

**적용 방안**:
- 기본: 핵심 정보만 표시 (반 이름, 시간, 진도 한 줄 요약)
- 확장: 클릭/호버 시 상세 정보 표시

### 3.2 Glanceability (한눈에 파악)

> "3초 안에 상황을 파악할 수 있어야 한다"

**적용 방안**:
- 색상 코딩으로 상태 표시 (정상/주의/위험)
- 아이콘으로 정보 유형 구분
- 숫자로 정량화 (제출률 85%, 진도 p.45)

### 3.3 Contextual Information (맥락 정보)

> "현재를 이해하려면 과거가 필요하다"

**적용 방안**:
- 지난 진도 → 오늘 진도 연결 표시
- 숙제 제출률 트렌드 표시

### 3.4 Scanability (스캔 가능성)

> "모든 것을 읽지 않고도 필요한 정보를 찾을 수 있어야 한다"

**적용 방안**:
- 시간순 정렬 (타임라인)
- 과목별 색상 구분
- 일관된 레이아웃 패턴

### 5.3 색상 체계

| 상태 | 색상 | 아이콘 | 의미 |
|------|------|--------|------|
| 정상 | 🟢 Green | ✓ | 완료, 전원 출석, 전원 제출 |
| 주의 | 🟡 Yellow | ⚠️ | 1~2명 미제출, 1명 결석 |
| 경고 | 🔴 Red | ❌ | 3명 이상 미제출, 다수 결석 |
| 미입력 | ⚪ Grey | - | 데이터 없음 |

### 5.4 진도 표시 형식

```
지난진도 → 오늘진도

예시:
- 페이지: p.42 → p.46
- 단원: 3과 → 4과
- 영어: U5 → U6
- 범위: Ch.3 → Ch.4
```

## 6. 데이터 요구사항

### 6.1 필요한 데이터

| 항목 | 소스 테이블 | 조회 방법 |
|------|-------------|----------|
| 지난 진도 | `progress` | 해당 반의 가장 최근 기록 |
| 오늘 진도 | `progress` | 오늘 날짜 기록 (있으면) |
| 지난 숙제 | `homework` + `submissions` | 가장 최근 숙제의 제출 현황 |
| 오늘 숙제 | `homework` | 오늘 배정된 숙제 |
| 특이사항 | `attendance` + `notes` | 결석자, 메모 |

### 6.2 API 설계

```typescript
interface ClassScheduleDetail {
  id: string;
  name: string;
  subject: string;
  teacher: { id: string; name: string };
  startTime: string;
  endTime: string;
  studentCount: number;

  // 진도
  lastProgress: {
    date: string;
    textbook: string;
    pageStart: number;
    pageEnd: number;
    topic: string;
  } | null;
  todayProgress: {
    pageStart: number;
    pageEnd: number;
    topic: string;
  } | null;

  // 숙제
  lastHomework: {
    description: string;
    submitted: number;
    total: number;
    notSubmitted: string[]; // 미제출자 이름
  } | null;
  todayHomework: {
    description: string;
  } | null;

  // 출결
  todayAttendance: {
    present: number;
    absent: number;
    late: number;
    absentNames: string[];
  } | null;

  // 특이사항
  notes: string[];
}
```

## 7. 개발 계획

### Phase 1: 기존 UI 제거 (5분)
- "현재 진행 중" 섹션 제거
- 기존 `ScheduleRow` 컴포넌트 백업

### Phase 2: 새 테이블 컴포넌트 (30분)
- `ClassScheduleTable` 컴포넌트 생성
- 시간대별 그룹핑
- 기본 정보 표시 (반, 강사, 진도 요약, 숙제 현황)

### Phase 3: 상세 정보 훅 (20분)
- `useClassScheduleDetail` 훅 생성
- progress, homework, attendance 조회

### Phase 4: 확장 패널 (20분)
- 행 클릭 시 상세 정보 표시
- 지난 진도, 오늘 진도, 숙제 상세, 특이사항

### Phase 5: 색상 및 아이콘 (10분)
- 상태별 색상 적용
- 아이콘 추가

### Phase 6: 액션 버튼 (15분)
- 출결 입력, 진도 입력, 숙제 배정 버튼
- 모달 연결 (기존 컴포넌트 활용)
